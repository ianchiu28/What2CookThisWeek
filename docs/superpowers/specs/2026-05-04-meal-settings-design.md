# 排餐設定頁面改版設計

## 背景

排餐設定目前以每天三餐的簡單勾選與單一 `dishCount` 呈現，無法表達午餐、晚餐需要幾菜、幾肉、幾湯，也讓頁面在資訊理解上偏陽春。這次改版要讓設定規則更貼近實際排菜單需求，同時維持與菜品設定頁一致的暖色卡片、chip 與簡潔表單風格。

## 目標

- 早餐只保留是否啟用的勾選，早餐固定只排 1 樣。
- 早餐候選菜品只使用分類為 `uncategorized` 且適用早餐的菜品。
- 午餐、晚餐可各自啟用，並設定 `菜 / 肉 / 湯` 三種數量。
- 午餐、晚餐的分類數量允許為 0。
- 每一天有總開關；關閉整天時，不顯示該日複雜設定 UI。
- 排菜單功能依新的分類數量產生 slots。

## 非目標

- 不新增「無分類」作為午餐、晚餐的數量設定。
- 不新增自訂分類。
- 不改動菜品設定頁的分類模型，仍維持 `uncategorized / vegetable / meat / soup`。
- 不新增跨日期批次套用功能。

## 資料模型

`MealSetting` 從單一 `dishCount` 擴充為三個分類數量：

- `vegetableCount`
- `meatCount`
- `soupCount`

早餐不使用這三個欄位；早餐排餐固定為 1 個 slot。為了讓資料結構一致，早餐設定仍會儲存這些欄位，但 UI 不顯示，預設值可為 0。

一天是否開伙不新增欄位，而是由該日三筆 `MealSetting.enabled` 推導：只要任一餐啟用，該日就是開伙；三餐皆關閉時，該日是不開伙。

## Migration

IndexedDB 新增 Dexie version migration：

- 既有 `dishCount` 會轉成 `vegetableCount`。
- `meatCount` 與 `soupCount` 預設為 0。
- 早餐不再依 `dishCount` 排餐；即使舊資料有早餐 `dishCount`，新邏輯仍固定排 1 樣。

這個轉換保留舊設定的「需要幾道」意圖，並用最保守的分類 `vegetableCount` 接住，避免舊資料直接失效。

## UI 設計

排餐設定頁維持單一主卡片，標題下加上簡短說明：「先選哪些天開伙，再設定每餐要安排的內容」。

每一天顯示成一張淡橘色日卡片：

- 頂部左側顯示週幾與狀態摘要，例如「週一 · 早餐、晚餐」或「週日 · 不開伙」。
- 頂部右側顯示整天開關。
- 整天關閉時，卡片視覺變淡，只保留頂部資訊。
- 整天開啟時，顯示早餐、午餐、晚餐設定列。

餐別列設計：

- 早餐：只顯示啟用 chip，旁邊顯示「固定 1 樣」。
- 午餐、晚餐：左側是啟用 chip，右側是三個小型數量控制，分別為「菜 / 肉 / 湯」。
- 午餐或晚餐啟用但三種數量合計為 0 時，顯示小提醒「這餐不會安排菜品」，但不阻止儲存。

整體視覺沿用菜品設定頁的 `card`、`choice-chip`、暖橘邊框與淡背景。行動裝置上維持單欄排列，數量控制可換行，避免表格型 UI 過度擁擠。

## 互動行為

- 關閉某一天：將該日早餐、午餐、晚餐的 `enabled` 全部更新為 `false`，保留午餐、晚餐既有分類數量。
- 開啟某一天：若該日三餐目前皆關閉，預設啟用晚餐；早餐與午餐維持關閉，避免一開啟就排三餐。
- 切換早餐：只更新早餐 `enabled`。
- 切換午餐或晚餐：只更新該餐 `enabled`。
- 調整午餐或晚餐分類數量：數量下限為 0，立即儲存。

## 排菜單邏輯

`generateWeeklyPlans` 依設定展開 slots：

- 停用餐別不產生 slots。
- 早餐產生 1 個 slot，候選菜品必須同時符合：
  - `mealTypes` 包含 `breakfast`
  - `category` 為 `uncategorized`
- 午餐、晚餐依 `vegetableCount / meatCount / soupCount` 展開 slots，候選菜品必須同時符合：
  - `mealTypes` 包含該餐別
  - `category` 等於該 slot 需要的分類
- 同一餐同一分類內避免重複菜品；若候選不足，額外 slot 保持未安排。

`WeeklyPlan` 仍保留既有欄位，不新增分類欄位；slot 的分類需求只在產生當下使用。

## 測試計畫

- `createDefaultMealSettings`：確認仍建立 21 筆設定，預設只有平日晚餐啟用，且分類數量合理。
- `generateWeeklyPlans`：確認早餐固定 1 slot 且只使用無分類早餐菜品。
- `generateWeeklyPlans`：確認午餐、晚餐依菜肉湯數量產生 slots，並只挑對應分類菜品。
- `generateWeeklyPlans`：確認分類候選不足時，額外 slot 保持未安排。
- App/UI 測試：確認排餐設定可以整天關閉與重新開啟，重新開啟空白日預設只啟用晚餐。
- App/UI 測試：確認早餐沒有數量輸入，午餐與晚餐可以把菜肉湯設定為 0。
- CSS 測試：確認新增的日卡片、餐別列與數量控制保留 chip/card 風格，且手機不使用擁擠表格。
